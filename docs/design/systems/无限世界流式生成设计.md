# 无限世界流式生成设计（chunk streaming）

## 0. 一句话

按固定 chunk 网格、只依赖 `(seed, chunkX, chunkY)` 确定性生成地貌，玩家周围的块按需生成、
远处淘汰——地图可无限延展，却从不一次性维护整张图。当前落在 **procgen 网页 demo**
（`tools/procgen-demo`，无限世界页 `mijing-infinite-demo.html`），零服务端红线。

## 1. 与有界秘境的根本区别

有界秘境（见 `秘境地形生成设计.md`）是 **BSP 分区 → 拓扑门位协商 → 全局 BFS 保证连通** 的副本：
它依赖「整张图的全体区域布局已知」，因此**天生无法无限**——没有全局矩形可切、没有「全体区域」
可协商门位、没有整张图可跑 BFS。

无限世界放弃这套，换成**连续自然地貌**：没有边界、没有房间、没有 entry/boss/宝库。
代价是失去有界副本的关卡结构，收益是真正的无限 + 惰性生成。二者是两套并存的系统，不互相取代。

## 2. 无缝的关键：世界坐标连续噪声

跨块无缝的充要条件——**同一世界坐标处的地形，无论由哪个块计算都相同**。

- 地形取自 `fbmNoise2D(worldX, worldY, seed, ...)`（`procgen-random.ts`），它按**世界坐标**采样、
  格点值由整数格点哈希决定，是整个无限平面上的连续函数。相邻块采样同一片噪声，边界值逐位一致。
- **绝不做「按本块 min/max 归一化」**（`generateField` 那套）——每块的 min/max 不同，会让边界
  地貌跳变，这正是分块拼接穿帮的根源。改为对原始 `[0,1)` 噪声施加**固定**对比拉伸
  `expand(v) = clamp01((v-0.5)*contrast + 0.5)`：处处同一映射，保持无缝。
- 地形分层用**固定阈值**的 biome 规则（高程/湿度区间，首条命中优先），不含任何 edgeDistance
  条件（无限图没有边）。

## 3. 平滑的 overscan

元胞多数派平滑（`smoothTerrain`）是 3×3 邻域，块边界处需要邻块的格子，独立平滑会在边界留痕。
解法：生成时带 **overscan**——多算一圈 `margin = smoothIterations + 1` 的格子，平滑后裁掉。
因每格按世界坐标确定性生成，overscan 的格子与邻块逐位一致，平滑跨界完全自洽。

## 4. 结构散布

树/竹/石/灵矿等按**逐块独立**的确定性种子 `${seed}:chunk:${cx}:${cy}:scatter` 撒，
只落在指定地形上。边界结构不需要邻块信息，故无跨块冲突。存 seed 即可复现，无需持久化像素。

## 5. 流式缓存（`InfiniteWorld`）

- `tileAt(worldX, worldY)`：世界格 → 所在块 → 缺块即 `generateChunk` 并缓存 → 取格。
  渲染基底与 dual-grid 融合都走它，故跨块读邻格天然自洽。
- `prefetch(cx, cy, r)`：预取相机所在块周围半径 r 的块（视口再外扩 1 圈，防走到边缘穿帮）。
- `evict(cx, cy, keep)`：淘汰距中心块超过 keep 的块——远处地图不再占内存，块数有界。

## 6. 渲染（`infinite-render.ts`）

世界坐标相机 `{x, y, cellSize}`：世界坐标落在画布正中。只画视口内的格（外扩 1 圈），
贴图走游戏运行时图包（`drawTile` 基底 + `drawDualGridTiles` 过渡边缘，与线上逐像素一致），
缺图集回退游戏同款底色 `TILE_VISUAL_BG_COLORS`。dual-grid 的 `offsetX = -camX*cellSize + W/2`
使世界网格对齐到相机，`tileAt` 回调直接吃世界坐标。

## 7. 默认世界

温带自然地貌：深水—浅滩—草原—丘陵—峭壁按高程分层，湿地（高湿低海拔）散生竹林，
草原生树、丘陵有石与灵矿。参数见 `INFINITE_WORLD_DEFAULT`（chunkSize 48，elevation/moisture
两张连续噪声场，contrast 2.4，2 次平滑）。

## 8. 验证

- **无缝**：3×2 拼块 ASCII 检视，山脉/水系/草原跨块连续、零跳变；无平滑时相邻块共享世界坐标处
  地形逐格连续。
- **确定性**：同块两次生成逐位一致；同 seed `tileAt` 逐格一致。
- **不穿帮**：模拟斜向远行 400 步（数千格），视口内始终有有效格。
- **内存有界**：远行 400 步后已载块数被 `evict` 夹在 `(2*keep+1)²` 内，不随行程膨胀。

## 9. 若要移植到服务端运行时（未做，仅记录）

探索结论：客户端天然分视野（AOI 只下发视野内格、按 mapId 稀疏记忆、相机分块渲染），
持久化可走「存 seed + 确定性重算」（通天塔已有先例）。真正的高风险障碍是**服务端每实例的
全图内存模型**（template 全图字符行 + RuntimeTilePlane 每格 activate + 寻路稠密全图 grid，
且禁止 tick 内 rehash）与**寻路的整图 grid 假设**。这些需专门设计，不在本次 demo 范围内。
