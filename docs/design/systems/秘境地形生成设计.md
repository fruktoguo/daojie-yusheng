# 秘境地形生成设计（分区拼装）

> 状态：**设计稿，未实现**。上位设定见 [秘境系统设计.md](./秘境系统设计.md)。
> 最后更新：2026-07-09

## 0. 一句话

保留现有 `generateProcgenMap` 的八步作为**开放地貌区**的生成器，在其之上加一层
**BSP 几何分区 + LevelGraph 拓扑中间表示**：每个区在自己的小数组里生成再 blit 回全局，
区间只在**生成前预留的门位**上连通。

## 1. 五个实证发现

设计前对现有代码做了实测（esbuild bundle + node 实跑），其中三条**推翻了纸面推导**。
所有后续决策建立在实测之上，不建立在代码注释之上。

### 1.1 `rng.fork(label)` 是顺序耦合的，且注释写反了

```ts
/** 派生一个独立子随机流，互不干扰（不同阶段各用各的流，避免顺序耦合）。 */
fork(label: string): ProcgenRng {
  return new ProcgenRng((hashStringToUint32(label) ^ Math.floor(this.next() * 4294967296)) >>> 0);
}
```
`procgen-random.ts:60-62`。那个 `this.next()` **消费父流状态**，于是子种子取决于 fork 的调用位次。

实测：同一 `seed-1`、同一 `fork('regions')`，仅因上游多调了一次 `fork('border')`，子流完全不同。

```
直接 fork("regions")               : 0.529194 0.940104 0.149388
先 fork("border") 再 fork("regions"): 0.663131 0.209009 0.801718
```

**后果**：任何人在管线里插入/删除一次 fork 调用，其后所有区域地形静默重新洗牌，无日志。
而秘境活过重启依赖 `(seed, L)` 逐位重建。玩家会站进墙里。

现有八步因 fork 顺序固定而暂时安全。分区拼装会引入按区/按边的动态 fork —— **必须堵死**。

**对策**：编排层以下硬禁 `parent.fork()`，改用不可变字符串种子纯函数派生（见 §7）。

### 1.2 `ensureConnectivity` 的问题不是「毁墙」，是「连接点不受控」

构造「左半完美迷宫 + 右半开放 + 中间实墙」（64×64）跑 carve：**只摧毁 7 格墙，0.6%**。
构造「迷宫 + 3 个未连通封闭密室」（48×48）：**摧毁 31 格，2.5%**。

墙体基本完好。真正的问题是：`carveCorridor`（`procgen-connect.ts:86-126`）连接的是
`collectRegionSamples` 按 stride 采样出的**曼哈顿最近点对**（`:193-211`），再带 25% 抖动随机游走过去。
**连接点位置与关卡设计毫无关系。**

实测图里能清楚看到，从密室凿出的隧道斜插进迷宫腹地，在墙上留下一串不受控的洞。
迷宫的游戏性来自路径长度；在墙上随机开 31 个洞 = 送一堆捷径。
地牢同理，玩家可以从密室侧墙钻进宝库，绕过设计好的门与 boss。

**结论：换掉 `ensureConnectivity` 的理由是「连接点不受拓扑控制」，不是「它毁墙」。**

### 1.3 `buildRoadNetwork` 不是瓶颈（我原以为是）

理论上 `open.includes` 是 O(n)、`for` 找最小是 O(n)，Dijkstra 退化为 O(V²)。实测不然：

| targets | 耗时 ms | 每 target ms | 路网格数 |
|---|---|---|---|
| 4 | 182 | 45.4 | 426 |
| 8 | 140 | 17.5 | 700 |
| 16 | 117 | 7.3 | 1009 |
| 24 | 131 | 5.5 | 1212 |
| 32 | 205 | 6.4 | 1436 |
| 48 | 251 | 5.2 | 1830 |

target 数翻 12 倍，总耗时只涨 38%。因为 `if (network.has(current)) break`（`procgen-routes.ts:149-152`）——
路网越密，后续 target 越早撞上已成网格子。**不要为这个不存在的瓶颈过度设计。**

### 1.4 真正的性能大头是 `smoothTerrain` 的每格 `new Map`

`bamboo_valley` @ 256×256，全管线 287ms：

| 步骤 | 耗时 | 占比 |
|---|---|---|
| `buildRoadNetwork`(4 targets) | 97 ms | 34% |
| `smoothTerrain`(2 iter) | 52 ms | 18% |
| `generateField` ×2 | 34 ms | 12% |
| `ensureConnectivity` | 24 ms | 8% |
| spawn + BFS | 22 ms | 8% |
| 其余七步 | 58 ms | 20% |

`smoothTerrain` 每格都 `const counts = new Map()`（`procgen-fields.ts:96`），65536 格 × 2 轮 = 13 万个 Map。
改成 tile→整数索引的调色板 count 数组（跨格复用、清零而非重建）可直接砍掉这 52ms。
**这是与分区无关的纯收益，可以独立先做。**

四个内置 preset 在 256×256 下均 130–206 ms，零 warning。

### 1.5 内置 preset 的尺寸太小，撑不起分区

`procgen-presets.ts` 四个 preset 的 `size` 是 `[56,72] × [44,60]`，面积 2464–4320。
按 `REGION_TARGET_AREA = 2400` 算，`N = round(area/2400)` 恒为 1–2，会被夹到 `Nmin`。

**分区拼装需要新的大尺寸 preset。** 完整的 entry→combat→vault→boss→exit 骨架
需要 N≥5，对应地板面积约 128²。小于 128² 时骨架必须坍缩（见 §8）。

## 2. 选型与理由

**骨干：BSP 几何分区。中间表示：借自「拓扑图先行」路线的 `LevelGraph`。**

两套候选方案（BSP 几何先行 / 拓扑图先行）各经 5 个镜头对抗性评审，**同为 27/50，且在 connectivity 上一起翻车（各 4/10）**。

**为什么几何用 BSP：** 「拓扑图先行」的图→几何嵌入被评审判为致命——
node↔叶匹配只消费 `node.depth`，完全不消费 `edge`，等于把二维任务图压成一维深度标量。
同深度的支线被塞进相邻环的远角，几何够不着就 portal 化，整套方案实际退化成
「深度排序同心环 + 传送补丁」，而它的招牌特性锁-钥恰好落在最常走的 portal 路径上、语义无定义。

反过来，BSP 被两个 expressiveness 评审**共同点名**的优点是：自底向上从 BSP 树抽出区域邻接图（RAG），
**RAG 恒与几何一致，没有「先画图后嵌入」的对齐漂移**。

**为什么表示用 LevelGraph：** BSP 的 RAG 只是内存邻接表，没有 gate 语义，表达不了锁-钥/支线/boss 前置。
把「拓扑图先行」的 `LevelNode` / `LevelEdge{keyId, lockId, depth, type}` 作为一等中间表示嫁接进来。

**次序是 几何 → 图 → 几何**：先 BSP 切几何，从中抽 RAG，再把 LevelGraph 的角色**回灌**到 RAG 节点上。
不做「先画抽象图再嵌入几何」。

**两方案共享的致命根因与同一修法**（本设计的承重件）：

> 门位必须是**生成前预留的构造不变量**，不是**生成后从空闲边格里捞**。

BSP 方案原提「复用受限的 `carveCorridor` 限制在 gutter 内」被判为「原语不支持的断言」；
拓扑图方案的 portal 被判「非格连通、`bfsDistances` 无法遍历、fill 模式会误删整片 boss 区」。
两者都死在同一件事上：**先生成、后连接**。

正解是反过来：对 RAG 每条边，**在任何区域生成之前**先确定门位（= 共享 gutter 边中点，对齐生成器 pitch），
把门位作为**强制通道**传入闭区生成器，令其从门格强制凿出 stub 直达最近的房间/通道。
于是「门 → 区内连通」成为构造不变量，§5 的归纳证明基例才真正成立。

## 3. 改造后的管线

`generateProcgenMap` 收敛为薄编排层（`procgen-generator.ts:85-233` 重排），领域逻辑下沉到新文件。

| 步 | 输入 → 输出 | 复用 / 新写 | 对应 file:line |
|---|---|---|---|
| S0 | preset, tiles → catalog, w, h | **复用** | `generator.ts:86-109`（`validateProcgenPreset` 增 partition/regions/topology 校验）|
| S1 | seed, area → `LevelGraph`（无坐标）| **新写** `procgen-topology.ts` | Dormans 文法展开 |
| S2 | 内矩形 R0 → BSP 树 + 叶表（nodeId, rect, gutter）| **新写** `procgen-partition.ts` | — |
| S3 | 叶表 + LevelGraph → RAG + 每叶 role/generatorType/**预留门位** | **新写** `procgen-topology.ts` | graph-distance BFS 选 boss |
| S4 | 叶 rect + role + 预留门 → 区内小数组生成 → blit 到全局三数组 | **新写** `procgen-regions.ts`；开放区复用**未改**的 `generateField`/`assignTerrain`/`smoothTerrain`/`placeStructures`/`placeBuildings` | `fields.ts:13,59,89`；`structures.ts`；`buildings.ts:160` |
| S5 | RAG 边 + edge.lockId → 沿 gutter 凿宽 1 轴对齐门廊 + door | **新写** `connectRegions` + `carveStraightCorridor`（有界 rect-clamp）| 取代 `connect.ts:86-126` |
| S6 | mask → 连通性 backstop（快退出）| **复用 + 改** | `connect.ts:158`（**禁用 carve 模式**）|
| S7 | terrain → `applyBorder` | **复用** | `fields.ts:123`（R0 已按其 inset 内缩）|
| S8 | mask, entry 叶 → spawn → `clearStructuresAround` → 可达性回填 | **复用 + 加约束参** | `routes.ts:34`；`generator.ts:148-160` |
| S9 | → `pickExits` + `buildRoadNetwork`(仅开放区) + `encodeRows` + 锚点可达断言 | **复用** | `routes.ts:64,119`；`generator.ts:184-232` |

**原样不改的基建**：`findRegions` / `buildWalkableMask` / `bfsDistances` / `encodeRows` / `stats` / `ProcgenRng` / `catalog`。

**关键手法：small-array + blit。** 每个区在自己的 `regionW × regionH` 小数组上生成，
再整体 blit 到全局 `(offsetX, offsetY)`。三重收益：

1. `smoothTerrain` 的 3×3 邻域天然 clamp 到小数组边界 = 区边界 → **冲突 B 免费解决，函数体一行不改**
2. 确定性天然干净：每区 = 自己的种子 + 自己的数组，与兄弟区的生成顺序解耦
3. 真正做到「复用而不改」

封装为 `RegionCanvas` 值对象（小网格 + `blitTo(global)`），避免各生成器到处穿 offset。

## 4. 分区算法

**对象**：`applyBorder` 内缩后的内部矩形 `R0`（`inset = maxBorderThickness + 1`）。

**区数**：
```
N = clamp(round(area(R0) / REGION_TARGET_AREA), Nmin = 2, Nmax = 24)
REGION_TARGET_AREA = 1600
```
用 `area(R0)` 而非原始 `W × H`。`1600` 是评审校正值——原提 `2400` 在生产 preset 尺寸下会让 `N` 恒被夹到 2
（见 §1.5），boss 区 footprint 必然 undersized，收益约等于零而风险全担。

**诚实标注**：完整的 entry→combat→vault→boss→exit 骨架需要 `N ≥ 5`，对应地板约 128²。
小于 128² 时骨架必须坍缩（见 §8）。

**切分**：叶子优先队列，按 `(area 降序, nodeId 升序)` 稳定 tie-break 消费。

`split(rect)`：
- 若 `long / short > 2.2` → 强制切长轴（防止细条，细条会自动降级为 corridor 区）
- 否则由 `partition` 字符串种子选轴
- 切点 `pos = int(minSide, len - minSide)`，**全整数运算**
- 两轴都不可分 → 标记为叶

**每叶之间保留 1 格 gutter 作为区间缝**，连接只在 gutter 内的预留门位打门。

**最小尺寸**：全局 `MIN_SIDE = 18`。各生成器的 footprint 门槛：

| 生成器 | 最小 footprint |
|---|---|
| dungeon | 30 × 30 |
| boss | 26 × 26 |
| maze | 16 × 16 |
| vault | 12 × 12 |
| corridor | 无下限 |

放不下时按 `dungeon → maze → open → corridor` **确定性降级**并 warn，绝不硬塞。

**形状**：切长轴 + `aspect ≤ 2.2` 保证叶近方正。类型分派前对叶质心跑一次平滑，
dungeon 叶必须聚成中心连通簇再定型（消除棋盘感）；`open` 与 `dungeon` 之间强制插入过渡叶
（洞窟/碎石 role）遮住正交硬缝。

**小图坍缩**：`N` 被夹到 2 时**坍缩拓扑**（boss 并入 combat、砍掉 vault 支线），退化为两块开放地。
**绝不抛 `procgen_partition_infeasible`** —— 秘境必须永远可实例化。

## 5. 区域生成器

新写 `procgen-regions.ts`。全部在 `RegionCanvas` 小数组上工作。

### 5.1 开放地貌（外圈 / 大叶）

小数组上跑**未改**的 `generateField` + `assignTerrain`（用该 zone 自己的 `terrainRules`，解决冲突 C）
+ `smoothTerrain` + `placeStructures` + `placeBuildings`。

**相邻 open 叶合并成一个 open macro-region，按其 union bbox 一次生成**。
原因：`generateField`（`fields.ts:31-36`）按数组自身的 min/max 归一化，逐区独立跑会让相邻 open 区的接缝处地貌跳变。
按 union bbox 单次生成则 min/max 连续（详见 §10.2）。

`smoothTerrain` **只在此类区跑** —— 实测 18% 的开销从此是上界而非常态。

### 5.2 迷宫（中层）：山崖地形迷宫

墙体是 **terrain 层的山体地形**（`cliff`），不是 structure 层的一格厚砖墙。
一格墙 + 一格路的做法渲染出来是网格纸迷宫，与秘境的山野观感冲突；而且 dual-grid
只有在相邻同类地形之间才会融合过渡边缘，砖墙永远是一格格孤立的方块。

拓扑与形态分离，分三步：

1. **拓扑**：`Recursive Backtracker`（随机化 DFS）跑在**低分辨率单元格**网上
   （间距 `cellPitch = 11~14` 格），产出生成树。`braidRate = 0.15 ~ 0.3` 做
   **dead-end braiding**（拆死胡同成环）—— 纯完美迷宫在 MMO 里会造成大量无效折返。
   braid 拆的是**拓扑边**，不是栅格里的某块砖。
2. **骨架**：把「单元格中心 + 相连单元格之间的**蜿蜒**线段 + 门位引线」栅格化进一个 mask。
   线段沿主轴推进、副轴按 `wobble` 概率随机偏移，偏移上限在两端线性收敛到 0，
   因此端点精确落在单元格中心上（端点漂移会把骨架撕成两截）。抖动幅度限制在
   `pitch/5` 以内，否则相邻通道频繁撞穿、山体碎成孤峰。
3. **形态**：对全区求 chamfer(3,4) 距离场，通道半径由柏林噪声调制
   （`radius = base ± base·roughness`）。`distance ≤ radius` 的格是通道，其余是山体；
   贴着山体的最外一圈铺 `slopeTile`（`hill`）作坡脚。
   噪声振幅必须够大（满幅时半径在 `[0, 2·base]` 摆动），否则量化到整数后边界几乎不动，
   山体退化成等宽直墙 —— 那就只是「墙变厚了的网格迷宫」。

**连通性**：骨架格 `distance = 0`，而 `radius ≥ 0` 恒成立，故整条骨架必然可走；
骨架连通且包含全部门位 ⇒ 门位天然接进通道，连事后凿 stub 都不需要。

但「骨架可走」不等于「通道内每格都走得到」：半径场逐格独立，
`{distance ≤ radius}` 会零星长出**孤岛** —— 某格靠对角贴着通道，四个正交邻居的半径
却略小、被判成山，这格便四面环山。让半径场平滑挡不住：chamfer 距离的最速下降方向
本身可以是对角，而游戏的可走性判定是四连通。
故按定义裁剪：**区内可走面 ≔ 从骨架出发四连通可达的部分**（`pruneToSeeds`）。
裁剪只会削掉贴边的孤立尖角，门位与骨架不受影响，构造不变量得以保持。

### 5.3 地牢（深处）

叶内嵌套 BSP，`splitDepth = floor(log2(area / roomTargetArea))`，`roomTargetArea ≈ 180`。
每个子格放一间 `minRoom = 5×5`、`jitter = int(1,3)` 的房。

**连接方式：递归连接子树的代表房**，而不是只连叶兄弟房。
（这是 connectivity 评审的 FATAL 修法：只连叶兄弟会留下割点，某些 port 到某些房不可达。）

兄弟房之间用 L 形直角走廊（宽 1，**无抖动**）连接，交点开 `door`。
预留门位从区边界向最近房凿 stub。

### 5.4 走廊区（细条叶）

单条 3 宽直线或肘形贯穿脊。纯连接组织，不放内容。

### 5.5 宝库 vault（拓扑关键叶）

单个封闭房、四面墙、**朝前驱侧仅 1 扇锁门**（由 `edge.lockId` 驱动）、对称柱阵、
中心 `chest` 锚点 + 可选 guard monster。确定性对称布局——读起来像「设计」而不是「随机」。

### 5.6 boss 房（图距最远叶）

大 chamber、墙环绕、朝前驱开 2–3 宽入口、四柱可选、中心 `boss` 锚点、清晰视野。
`exit` portal 紧邻其后。

参数全部走 `nodeId` 字符串种子。锚点 `kind` 从 `chest|monster` 扩展到 `+boss|herb|scripture|lock|key`。

## 6. 区间连接与连通性证明

**连接 = 构造不变量。** 替换掉会横穿任意墙体的全局 `carveCorridor`（`connect.ts:86`，25% 抖动、无边界约束）。

### 6.1 预留门位（承重修法）

对 RAG 每条边，**在任何区域生成之前**先确定门位：
- 门位 = 共享 gutter 边的中点
- 作为**强制通道**传入闭区生成器：
  - maze 把门位直接接进通道骨架（骨架恒可走，故门位恒可走）
  - dungeon / vault / boss 从门格凿 stub 直达最近房间，或 `punchDoors` 打穿周界
- 门位**不需要**对齐任何 pitch。旧设计让门位对齐迷宫的奇数廊格，那是砖墙迷宫
  「少凿一格墙」的补丁；地形迷宫的门位落在哪都能长出一条峡谷通道过去。

于是「门 → 区内连通」是构造不变量，归纳证明的基例真正成立。

### 6.2 连边（S5）

新写 `carveStraightCorridor`：**有界 rect-clamp、无抖动、宽 1、轴对齐直线或肘形**。
只在 1 格 gutter 内凿，**绝不进入任何区的内部矩形**。两端在区墙上 punch door。

`lockId` → 目的区的门改为 lock 结构；`key` 锚点落在持有对应 `keyId` 的节点区内。

### 6.3 传送阵：降格为纯冗余 cross-link

设计目标里写了「区间靠走廊或传送阵连」。但 intra-map portal 有**三重不兼容**：

1. `bfsDistances`（`routes.ts:12`）是纯四连通 BFS，**无法遍历 portal**
2. `ensureConnectivity` 的 fill 分支（`connect.ts:187-190`）会把 portal 连接的独立格块当作非主区**删掉**
3. 输出契约 `ProcgenPortalPlacement` 只有 `role: 'entry' | 'exit'`；而地图 document 白名单重建会丢弃自定义顶层字段，
   N 对 intra-map 配对**无处编码**

**解法：portal 只允许加在两个已经格连通的区之间成环，绝不作为任何区/锚点的唯一连接。**

于是三重不兼容全部降为非致命：BFS 视角缺席无所谓（区仍格可达）、fill 误删无所谓（区另有走廊连接）、
配对信息用一等返回字段 `portalPairs` 承载（不进 document 顶层）。运行时若不支持 intra-map teleport，
直接丢弃 portal，走廊保底连通不变。

**代价（诚实标注）**：放弃「用传送折叠深区距离」的表达力，深层宝库/boss 无法靠传送做前置。这是已知的表达力上限。

### 6.4 连通性证明（对 BSP 树归纳）

**基例**：每个叶生成器保证区内单连通。
- 迷宫 = 骨架连通（生成树）+ 可走面按四连通可达性裁剪到骨架（`pruneToSeeds`）
- 地牢 = 递归连接子树代表房形成的连通树
- open / vault / boss = 在本区小数组内跑局部 `findRegions` 修复，**只 fill 不 carve**

**归纳**：内部节点的两个孩子 A、B 各自连通（归纳假设），`connectRegions` 经预留门位至少凿一条门廊连接 A ∪ B。

**根连通 ⇒ 全图单连通。** 环 link 与 portal 只加边、不破坏连通性。

### 6.5 backstop（S6）

`findRegions` 跑一次，`== 1` 立即 return（**快退出，把实测的 24ms 变成近 0**）。
仅回填 `< fillThreshold` 的真·噪声孤块。若出现大块非主区残留（说明预留门位有 bug）→
在 gutter 内有界重凿 → 仍失败则 `throw procgen_connectivity_failed`。

**禁用 `mode: 'carve'`。** 注意四个内置 preset（`procgen-presets.ts`）全部是 carve 模式——
所以 backstop 横穿墙体是**常态而非罕见**，BSP 方案原文在这一点上判断错误。

### 6.6 spawn 反修

保留「全局最大连通块内选点」（`generator.ts:141`），**仅在已属主块的格内**偏向 entry 叶。
绝不允许 spawn 落在少数派连通分量上——否则 `bfsDistances` 只覆盖那个口袋，
S8 的可达性收尾会把全图其余部分当作不可达而回填删空。

## 7. 拓扑骨架与类型

### 7.1 LevelGraph（内存态，不进 document）

```ts
// procgen-topology.ts。随 ProcgenMapResult 返回给调用方，不写入地图 document
// （document 白名单重建会静默丢弃自定义顶层字段）
interface LevelNode {
  id: number;                    // 按创建序稳定分配
  type: 'entry' | 'combat' | 'vault' | 'boss' | 'exit' | 'branch' | 'hub';
  depth: number;                 // 从 entry 起的无向 BFS 距离
  keyId?: number;                // 该节点持有的钥匙组
}

interface LevelEdge {
  id: number;
  from: number;
  to: number;
  kind: 'corridor' | 'portal';   // portal 仅作纯冗余 cross-link
  lockId?: number;               // 锁门；depth(key) < depth(lock) 保证可解
  critical: boolean;             // 临界路上的边 → 禁 braid、禁旁路
}

interface LevelGraph { nodes: LevelNode[]; edges: LevelEdge[] }
```

### 7.2 RAG（从 BSP 抽出，与 LevelGraph 对齐）

```ts
interface RegionNode {
  nodeId: string;                // BSP 路径串，如 "R.0.1"
  rect: { x: number; y: number; w: number; h: number };
  generatorType: 'open' | 'maze' | 'dungeon' | 'vault' | 'boss' | 'corridor' | 'transition';
  role: LevelNode['type'];
  depth: number;
  ports: { edge: 'N' | 'E' | 'S' | 'W'; doorX: number; doorY: number; toNodeId: string; lockId?: number }[];
}
```

### 7.3 图 → 几何的映射（次序：几何 → 图 → 几何）

1. **几何 → 图**：自底向上从 BSP 树抽出 `RegionNode` 邻接图。RAG 邻接表按 `nodeId` 有序构建。
2. **角色回灌**：
   - `entry` = 某个外圈开放叶
   - `boss` = 从 entry 在 RAG 上跑 **graph-distance BFS**，取「图距最远且满足 boss footprint」的叶
     （两方案的评审共同点名：这比「最深的 BSP 叶」鲁棒，且唯一确定了临界路）
   - `critical path` = entry → boss 的最短路
   - `vault` = 挂在临界路上的**真·死端旁支叶**（度 = 1）。找不到就 warn 降级，
     **绝不提升为「boss 前一个节点」**——那会把「可选」变成「必经」
   - `combat` = 临界路上的中间叶
   - `exit` = boss 叶或其相邻叶，放 exit portal
   - filler = 离路的叶，按地形表撒草药/杂兵
3. **门控保护**：critical 边打 no-braid 标记；环 link 只加在非临界子树上；
   boss/vault 的咽喉边永不加旁路 → **空间前置从「概率成立」变成「构造保证」**

## 8. 确定性方案

**编排层以下硬禁 `parent.fork()`**（理由见 §1.1）。改用不可变字符串种子纯函数派生：

| 用途 | 种子 |
|---|---|
| 分区 | `` `${seed}:${preset.id}:partition` `` |
| 每区 | `` `${seed}:${preset.id}:region:${nodeId}` `` |
| 拓扑 | `` `${seed}:${preset.id}:topology` `` |
| 连边 | `` `${seed}:${preset.id}:join:${edgeId}` `` |

`nodeId` 是 BSP 路径串，与兄弟遍历顺序解耦 → 可并行、可单区重算。实测两次独立构造恒等。

**铁律**：
- 绝不迭代 `Map` / `Set` 来做选择。RAG 邻接、cross-link 候选、port 候选一律用按 `nodeId`/坐标预排序的数组
- 排序键末位追加 index 作全序 tie-break（照抄 `routes.ts:67` 的 `|| a - b` 范式）
- 切点全整数运算；浮点只允许进噪声采样
- anchor / warnings / edge 写入按 `nodeId` 键的定长槽，最后按 `nodeId` 排序串接。
  **禁止并行 push 到共享数组**（determinism 评审的 FATAL）

**金标哈希测试作发版门禁**：同 `(seed, preset, catalog)` 跨 Node 版本、跨 arch，断言 `finalRows` 逐位相等。

## 9. 性能与失败模式

### 9.1 性能（基线 287ms / 256²）

**省**：
- `smoothTerrain` 只在 open 区跑：−15~25 ms（18% 是上界，不是净赚）
- backstop 快退出：24 ms → ~0

**真正的大头修**（三个 performance 评审共识，与分区无关）：
- `smoothTerrain` 每格 `new Map`（`fields.ts:96`）→ tile→整数索引调色板 count 数组，跨格复用清零。**直接砍掉 52ms**
- `buildRoadNetwork`（97ms / 34%，最大单项）：闭区不跑 Dijkstra，直接复用 `connectRegions` 的门廊作路骨架，
  只在 open 区画路。per-target 的 typed array 提到循环外复用 + generation-stamp 代替 `.fill()`

**加**：
- 逐区 small-array + blit（三数组瞬态拷贝，+5~10 ms）
- per-region 局部 BFS

**估算**：与基线同量级到 +10~15%（约 300–330 ms）。生成在实例创建期、不进 tick，可接受。

⚠️ **峰值内存需设「同时生成实例数」上限**：small buffer 之和 + 全局三数组在 blit 期约 2× 瞬态。
10000 实例的并发尖峰会撞内存。

⚠️ 上述 buildRoadNetwork 结论是在 `bamboo_valley` 这种**开放地貌**上测的，
不能外推到 maze/dungeon-heavy 的 preset。阶段 4 必须重测。

### 9.2 失败模式与口径

| 情形 | 处理 |
|---|---|
| 区放不下其生成器 | 按 `dungeon → maze → open → corridor` 确定性降级 + warn |
| `N` 被夹到 2（小图） | **坍缩拓扑**（boss 并入 combat、砍 vault 支线），绝不抛错 |
| vault 找不到真·死端旁支 | warn 降级，**绝不**提升为 boss 前置节点 |
| `< fillThreshold` 的噪声孤块 | 静默 fill |
| 大块非主区残留 | gutter 内有界重凿 → 仍失败则 `throw procgen_connectivity_failed` |
| 关键锚点不可达 | 重定位 + warn |
| 坐标越界 | 生成器自校验（运行时是静默 clamp/丢弃，不会报错）|

**原则**：秘境必须永远可实例化。只有连通性彻底崩坏（说明预留门位有 bug）才抛错。

## 11. 开放问题（诚实标注）

### 11.1 多锁 DAG 的可解性校验尚未落地
`LevelGraph` 已泛化为支持多锁 DAG（`lockCount` 区间），但**「拓扑排序保证每把锁在其钥匙可达之后」的算法细节未定**。
阶段 3 必须补上 DAG 可解性证明，否则退回单锁保守形态（`depth(key) < depth(lock)`）。

### 11.2 开放区跨区连续 vs small-array 确定性
`generateField`（`fields.ts:31-36`）按数组自身的 min/max 归一化，逐区独立跑会让相邻 open 区的接缝跳变。

已选解法：相邻 open 叶合并成一个 macro-region，按 union bbox 单次生成（`generateField` 不改，union 内 min/max 连续）。
非 open 区完全隔离在自己的 small-array 里。**残留问题**：只在 open ↔ open macro 之间可能出现窄 blur 带（罕见）。

备选是固定仿射归一化，但会让地貌配比随 preset 的噪声分布漂移。**取「区内连续 + 接受稀有窄缝」这一侧。**

### 11.3 矩形规整观感是几何先行的固有上限
BSP 本质是切盒子。开放地貌被切成方块不自然，迷宫/地牢的边界是正交硬缝、没有对角地貌。
质心平滑 + 过渡叶 + 全局噪声流穿缝只能缓解，不能根治。

放弃了 Voronoi + Lloyd 松弛（边界与格网对不齐、非凸区难以嵌入迷宫/地牢）——
这是为「生成器一定放得下 + 格网对齐」付出的代价。

### 11.4 intra-map 传送阵的表达力上限
见 §6.3。portal 降格为纯冗余 cross-link 后，无法用传送折叠深区距离，深层宝库/boss 不能靠传送做前置。
