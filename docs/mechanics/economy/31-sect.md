## 宗门角色与权限

源文件: `packages/shared/src/sect-types.ts`

### 角色

| 角色 | 中文 |
|------|------|
| leader | 宗主 |
| supreme_elder | 太上长老 |
| deputy | 副宗主 |
| elder | 长老 |
| inner | 内门 |
| outer | 外门 |
| labor | 杂役 |

职位等级固定为：`宗主 > 太上长老 > 副宗主 > 长老 > 内门 > 外门 > 杂役`。

### 权限

| 权限 | 说明 |
|------|------|
| guardian | 护宗大阵操作 |
| member_remove | 逐出宗门 |
| member_approve | 查询、同意或退回入宗申请 |
| member_role | 修改职位 |
| building_create | 在宗门地图放置和继续建造建筑 |
| building_remove | 在宗门地图拆除建筑 |

### 默认权限分配

- leader/supreme_elder/deputy: 全部六项权限
- leader/supreme_elder 的权限固定为全开，不允许关闭
- elder: 仅 guardian
- inner/outer/labor: 无权限

只有宗主可以编辑普通职位的权限。太上长老可由宗主任命，并固定拥有全部六项职位权限；宗主转让、宗门解散和职位权限配置仍是宗主专属能力，不属于可配置职位权限。

拥有 `member_role` 权限的成员只能修改职位严格低于自己的成员，也只能把目标任命为严格低于自己的职位；不能修改自己，宗主职位只能通过宗主转让改变。

宗门地图的建筑放置、继续施工和拆除分别由 `building_create`、`building_remove` 权限裁定。拥有拆除权限者可以管理宗门领地内其他成员的建筑，但宝库库存返还、密室释放等资产安全流程不得绕过。非宗门地图继续使用建筑系统原有权限规则。

## 宗门功能

- 建宗: 在指定位置创建宗门领地
- 迁宗: 宗主或副宗主可使用「迁宗令」将宗门山门入口传送阵迁至当前所在的大地图现世线位置；宗门地图和核心坐标不变。迁移冷却为 3 天，绑定宗门，不绑定玩家。
- 宗门地图: 独立持久实例，非虚境完整权限，允许 PVP、地块攻击和阵法相关玩法
- 坐标: 宗门核心固定在 (0,0)，领地扩展使用真实正负坐标边界，不再通过模板中心偏移移动地图
- 扩展: 通过击败地块扩展领地
- 先天固脉: 宗门核心 `SECT_INNATE_STABILIZER_RADIUS` 范围内视为固脉效果，暂停地块复生/临时地块消散，并给受损但未摧毁的系统地块、玩家建筑地块和技能临时地块提供每息 `1%` 最大生命的额外恢复；该回血与固脉阵同源，不叠加。
- 护宗大阵: 初始灵力 100000、默认控制强度 1、初始灵石 1000，提供边界屏障；宗门管理面板可调整控制强度并查看当前减伤、剩余灵石和预计可维持天数
- 成员管理: 入宗审批/逐出宗门/职位变更

### 入宗申请审批列表

- 仅拥有 `member_approve` 权限的宗门成员可以查询、同意或退回待处理拜帖。
- 申请列表属于低频详情请求，不嵌入随上下文行动刷新的 `sect:manage` 完整描述；管理摘要只携带宗门 ID、待审批总数与宗门版本，客户端以该摘要中的宗门 ID 隔离迟到回包。
- 客户端通过 `RequestSectApplicationPage` 按搜索词、偏移量和数量请求，服务端通过当前登录玩家推导宗门并返回 `SectApplicationPage` 单播响应。
- 搜索在服务端先匹配申请人姓名或玩家 ID，再分页；默认每页 `20` 条，单次最多 `50` 条。
- 请求与响应携带 `requestId`，响应同时携带宗门 `revision`；客户端必须拒绝迟到请求或落后于已知宗门版本的结果。
- 审批后仍由服务端权威 mutation 更新宗门、成员关系和持久化状态；分页查询只读运行态，不直接修改宗门。

## 持久化与恢复约束

- 建宗、迁宗会在同一数据库事务内提交宗门版本、建宗令/迁宗令所在背包和护宗大阵位置；宗门成员及权限变更使用宗门版本 CAS，拒绝旧节点覆盖新状态。
- 宗门 `updatedAt` 是严格递增的并发版本，不允许一次 mutation 沿用旧版本。
- 山门与宗门核心传送门是 `server_sect` 的运行时派生投影，不写入实例 overlay；启动和实例恢复时按当前宗门入口重建，避免迁宗后恢复出旧入口。
- 护宗大阵只在当前 `entranceInstanceId` 恢复；历史孤儿或旧入口阵法会在恢复时清理。
- COMMIT 结果暂时无法确认时，当前宗门队列锁与相关玩家资产锁保持占用并持续回读；确认未落地才在原 mutation 内重试。禁止把旧玩家投影放入后台内存队列延后覆盖，也不能在结果未定时向后续宗门 mutation 或普通文档刷盘放行。
- 审批入宗、主动退出和移除成员都在持有目标玩家锁后再次核对其当前宗门；若归属已变化，释放并按新旧宗门的稳定锁集合重试，禁止在未持有真实归属宗门队列锁时改写成员关系。
- 解散宗门先持有宗门队列锁，再读取当前完整成员列表并一次性取得所有成员资产锁；不得使用排队前的成员快照，否则等待期间新加入的成员可能漏锁。
- 地块破坏触发的领地扩张与管理操作共用同一宗门队列；管理事务等待数据库期间，tick 扩张只能排队，不能越过后被失败回滚覆盖。
- 普通宗门文档保存先固定本轮宗门 ID 集合并取得对应宗门锁，再作为一个 durable commit queue 任务采样和写库；新建宗门留给自身强事务，禁止普通 save 抢先暴露尚未原子提交的宗门快照。
- 生产配置了数据库时，共享连接池缺失、建表或核心坐标自愈失败必须让宗门恢复和资产变更 fail-closed；只有完全未配置数据库的本地模式可使用内存态回退。
- 职位权限保存在宗门 `raw_payload` 中；恢复旧快照时只为缺失的新权限补默认值，已有显式开关保持不变，宗主和太上长老始终归一为全部权限。
