## 宗门功能

- 建宗: 在指定位置创建宗门领地
- 迁宗: 宗主或副宗主可使用「迁宗令」将宗门山门入口传送阵迁至当前所在的大地图现世线位置；宗门地图和核心坐标不变。迁移冷却为 3 天，绑定宗门，不绑定玩家。
- 宗门地图: 独立持久实例，非虚境完整权限，允许 PVP、地块攻击和阵法相关玩法
- 坐标: 宗门核心固定在 (0,0)，领地扩展使用真实正负坐标边界，不再通过模板中心偏移移动地图
- 扩展: 通过击败地块扩展领地
- 先天固脉: 宗门核心 `SECT_INNATE_STABILIZER_RADIUS` 范围内视为固脉效果，暂停地块复生/临时地块消散，并给受损但未摧毁的系统地块、玩家建筑地块和技能临时地块提供每息 `1%` 最大生命的额外恢复；该回血与固脉阵同源，不叠加。
- 护宗大阵: 初始灵力 100000、默认控制强度 1、初始灵石 1000，提供边界屏障；宗门管理面板可调整控制强度并查看当前减伤、剩余灵石和预计可维持天数
- 成员管理: 邀请/移除/职位变更

## 持久化与恢复约束

- 建宗、迁宗会在同一数据库事务内提交宗门版本、建宗令/迁宗令所在背包和护宗大阵位置；宗门成员及权限变更使用宗门版本 CAS，拒绝旧节点覆盖新状态。
- 宗门 `updatedAt` 是严格递增的并发版本，不允许一次 mutation 沿用旧版本。
- 山门与宗门核心传送门是 `server_sect` 的运行时派生投影，不写入实例 overlay；启动和实例恢复时按当前宗门入口重建，避免迁宗后恢复出旧入口。
- 护宗大阵只在当前 `entranceInstanceId` 恢复；历史孤儿或旧入口阵法会在恢复时清理。
- COMMIT 结果暂时无法确认时，当前宗门队列锁与相关玩家资产锁保持占用并持续回读；确认未落地才在原 mutation 内重试。禁止把旧玩家投影放入后台内存队列延后覆盖，也不能在结果未定时向后续宗门 mutation 或普通文档刷盘放行。
- 审批入宗、主动退出和移除成员都在持有目标玩家锁后再次核对其当前宗门；若归属已变化，释放并按新旧宗门的稳定锁集合重试，禁止在未持有真实归属宗门队列锁时改写成员关系。
- 解散宗门先持有宗门队列锁，再读取当前完整成员列表并一次性取得所有成员资产锁；不得使用排队前的成员快照，否则等待期间新加入的成员可能漏锁。
- 地块破坏触发的领地扩张与管理操作共用同一宗门队列；管理事务等待数据库期间，tick 扩张只能排队，不能越过后被失败回滚覆盖。
- 普通宗门文档保存先固定本轮宗门 ID 集合并取得对应宗门锁，再作为一个 durable commit queue 任务采样和写库；新建宗门留给自身强事务，禁止普通 save 抢先暴露尚未原子提交的宗门快照。
